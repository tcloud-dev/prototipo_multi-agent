# prototipo_multi-agent

Protótipo de sistema multi-agent. Hoje há agentes para Jira (`jira-assistant`), commits e PRs (`atomic-commits`), leitura do Figma (`designer`) e criação de landing page (`programmer`, `qa-visual`, `minifier`), e as skills que eles usam; a ideia é crescer para mais agentes por domínio, coordenados entre si. Nome anterior do repositório: `prototipo_agent_atlassian`.

## Direção multi-agent

- **Decidido:** o repositório é multi-agent; cada agente tem uma responsabilidade e usa skills próprias, tudo em `.ia/` (fonte única).
- **Decidido (2026-11-03):** o fluxo da landing page é orquestrado por uma **skill** (`build-landing`) rodando na sessão principal, não por um agente: `designer` → `programmer` → `qa-visual` (laço com o usuário, máx. 3 rodadas) → `minifier`.
- **Em aberto (não assumir):** se haverá um agente orquestrador para os demais domínios, quais agentes novos entram, como eles se comunicam e como o aviso periódico a usuários será entregue (hoje não há agendador nem canal de envio; ver `jira-assistant` abaixo). Pergunte ao usuário antes de criar agente ou orquestrador novo.
- O plugin se chama `multi-agent` em `.ia/.claude-plugin/plugin.json` (antes `atlassian-agent`, renomeado a pedido do usuário em 2026-10-20); o nome é o prefixo das skills e dos agentes (`multi-agent:jira-cards`), então só renomear com pedido do usuário.

## Estrutura

- **Fonte única:** tudo de IA vive em `.ia/` (`.ia/skills/`, `.ia/agents/`, ...). `.ia/` é a raiz do plugin do Claude Code (`.ia/.claude-plugin/plugin.json`, skills em `.ia/skills/` pelo padrão); testar com `claude --plugin-dir .ia`. Para o Copilot, `.github/skills/<nome>/SKILL.md` e `.github/agents/<nome>.agent.md` são **apenas ponteiros** (frontmatter + "leia `.ia/...`"), sem conteúdo próprio. Ao criar skill/agente novo em `.ia/`, crie o ponteiro correspondente em `.github/`. Nunca colocar lógica nos ponteiros.
- `.claude-plugin/marketplace.json` (raiz) publica o plugin `.ia/` como marketplace `tcloud-multi-agent` para uso em outros repositórios. Dentro de `.ia/`, caminhos de agentes e skills usam `${CLAUDE_PLUGIN_ROOT}` (não `.ia/`); `figma-map.mjs` grava em `figma-data/` da raiz git do diretório atual. `permissions.deny` não viaja com o plugin: `.ia/hooks/guard.mjs` repete a lista (manter as duas iguais).
- Release: uma por merge na `main`, consumidores seguem tag `vX.Y.Z`; processo e workflow (ainda não criado) em `RELEASING.md`. Skill `.ia/skills/setup/` prepara o repositório consumidor (attribution, .gitignore, requisitos).
- `.ia/.claude-plugin/plugin.json`: manifesto do plugin (a pasta `.claude-plugin` tem nome obrigatório).
- `.ia/skills/jira-cards/SKILL.md`: skill que cria, edita e transiciona cards via MCP da Atlassian. Nunca deleta, não cria projetos e sempre confirma antes de escrever. Trata a hierarquia (épico > história/tarefa > subtarefa; subtarefa exige pai; o pai nunca é escolhido sozinho), checa duplicidade, cria em lote com plano único e usa `templates.md` para descrições.
- `.ia/agents/jira-assistant.md`: agente que usa a skill `jira-cards`. Proibido deletar: a lista `tools` do agente **não** é uma trava (testado: comando fora da lista foi executado); a trava real é a regra `deny` de `executeDestructive` em `.claude/settings.json`. Limitação: como subagente, ele não aceita confirmação repassada pelo agente principal, então só lê; criar/editar/transicionar é feito na sessão principal após o "sim" do usuário (ver `jira-cards/SKILL.md`). Ponteiro do Copilot em `.github/agents/jira-assistant.agent.md`.
- `.ia/agents/atomic-commits.md` + skills `.ia/skills/commit-conventions/` (com `profiles/<repo>.md`), `.ia/skills/pr-summary/` e `.ia/skills/branch-cleanup/`: commits atômicos PT-BR sem acento, com chave do Jira. A `branch-cleanup` apaga, local e remoto, só branches `feat/fix/bugfix/docs` do próprio usuário, depois que ele confirma que o trabalho acabou e o tip está em `env/dev`, `env/hmg` e `main` (nunca `-D`; plano com um único "sim"). Ponteiro do Copilot em `.github/skills/branch-cleanup/`. Lista de comandos proibidos (rebase, reset, push forçado, amend, --no-verify, add . / -A) fica em `commit-conventions/SKILL.md` (regra de texto, vale para qualquer IA) e é bloqueada tecnicamente no Claude Code por `permissions.deny` em `.claude/settings.json`; no Copilot só vale o texto; push automático só em `feat/**`, `fix/**`, `bugfix/**`. Fluxo de branches TOTVS em `commit-conventions/git-flow.md`: protegidos `main`, `env/hmg`, `env/dev`; merge commit (sem squash/rebase).
- `.ia/agents/designer.md` + scripts `.ia/scripts/figma/` (`figma-map.mjs`, `contrast.mjs`, `lib/` com testes: `node --test .ia/scripts/figma/lib/*.test.mjs`): extrai tudo que o Figma expõe pela API REST (nunca pelo MCP; não escreve no Figma) e guarda em `figma-data/<fileKey>/` (`index.json`, `README.md`, `design-system.md`, `pages/`, `assets.json`, `assets/`, `refs/`; `raw/` é JSON bruto e fica fora do git). Token em `FIGMA_TOKEN` ou `~/.config/figma/.env` (fora do repo, nunca lido nem exibido). Atrás do proxy da TOTVS o HTTPS usa CA própria: o script já confia nas CAs do sistema (`tls.setDefaultCACertificates`); em Node sem essa API, rodar com `NODE_USE_SYSTEM_CA=1`; nunca desligar a validação de certificado. Economia de tokens é requisito: os scripts gravam em arquivo e o agente consulta com `grep` e `jq` (macOS/Linux) ou `node -e` (Windows, sem `jq`). Ponteiro do Copilot em `.github/agents/designer.agent.md`. Origem: agente de outro repositório, desacoplado do `site-spec`/`builder`.
- `.ia/agents/programmer.md` + skill `.ia/skills/landing-page/`: landing page em HTML5, CSS3 escrito em **SCSS** e JavaScript ES2022 puros (sem framework) em `src/app/` do repositório consumidor, lendo só o `figma-data/<fileKey>/` do `designer`. Contrato com o QA: cada seção tem `id`, `data-figma-node` (variante `desktop-light`) e `data-figma-<variante>` (`mobile-light`, `desktop-dark`...). Skills de tecnologia: `html5`, `css3` (com `scss-guide.md`, o guia de SCSS da equipe: `@use`, BEM aninhado, tokens como custom properties) e `javascript-es`; a `landing-page` só guarda estrutura e contrato. O `css/` compilado (`npm run sass`) é gerado, fica no `.gitignore` do consumidor e é o que o QA lê. Relatórios e log em `reports/` (`build-log.md`, `qa/`).
- `.ia/agents/qa-visual.md` + skills `.ia/skills/qa-visual/` (laço de QA com o usuário) e `.ia/skills/build-landing/` (orquestrador do fluxo completo, retomável pelos artefatos): scripts `.ia/scripts/qa/` (`qa-capture.mjs` abre `src/app/` com Playwright e mede cada seção; `qa-compose.mjs` monta o lado a lado Figma × site com `sharp`). Consulta de documentação (decidido 2026-11-03: **sem RAG vetorial por ora, talvez nunca**): `.ia/scripts/docs/docs.mjs` (`sync`, `search`, `show`) baixa por git raso o conteúdo da MDN (html, css, javascript, api, accessibility) e da documentação do Sass para `~/.cache/multi-agent/docs` (fora do repo), monta um índice JSON e responde com uma linha por página ou só a seção pedida; o `programmer` também tem `WebFetch` limitado a MDN, web.dev e sass-lang.com (sintaxe `WebFetch(domain:...)` no `tools` ainda não confirmada). Os scripts de QA resolvem `playwright` e `sharp` a partir do **repositório consumidor**, não do plugin.
- `.ia/agents/minifier.md` + `.ia/templates/build/build.mjs`: `src/app/` → `dist/app/` (HTML com html-minifier-terser, SCSS compilado com `sass` e minificado com esbuild (a pasta `scss/` não vai para o `dist`), JS com esbuild (alvo es2022), imagens com sharp, SVG com svgo, vídeo com ffmpeg-static; confere referências quebradas). **O script mora no repositório consumidor** (`scripts/build.mjs`, copiado pela skill `setup`) porque o GitHub Actions do deploy roda o mesmo `npm ci && npm run build`; o template do plugin é só a origem da cópia. Testado: `NODE_USE_SYSTEM_CA=1` no `npm i` atrás do proxy; npm 12 bloqueia scripts de instalação (`npm approve-scripts`). `.gitignore` do plugin libera `.ia/templates/build/` (a regra `build/` o ignoraria). `dist/`, `src/app/css/` e `reports/qa/` ficam fora do git do consumidor. Scripts do repositório são `.mjs` de propósito (módulo ES garantido pelo Node sem depender do `type` do `package.json` do consumidor); TypeScript descartado por ora, e a migração futura prevista é para Python. Ponteiros do Copilot em `.github/`.
- `.ia/skills/jira-cards/teams/<projeto>.md`: padrões de preenchimento por equipe (hoje só `tci.md`). Os campos obrigatórios são sempre descobertos pela API, não deste arquivo.
- `.vscode/mcp.json`: MCP da Atlassian para o Copilot no VS Code (OAuth no navegador, sem segredos no arquivo). No Claude Code o acesso vem do connector da conta claude.ai.
- Sem API key da Anthropic por decisão do usuário: não adicionar código que dependa de SDK pago sem confirmar.
- Manter a skill neutra de fornecedor (formato SKILL.md, MCP) para funcionar também no GitHub Copilot.
